# Actual example evidence

These artifacts were generated by real executions on 2026-11-01. They are retained teaching examples, not prepopulated dashboard completion results or claims about a future checkout.

- `local-test-evidence.json`: unmodified observation file from the Windows/Python 3.13.18/Chromium execution. It includes 52 actual scenario observations. The development worktree was in progress; this is execution evidence rather than a claim that every observation corresponds to a clean Git revision. See `docs/verification.md` for the latest complete local count and coverage.
- `hosted-training-evidence.json`: actual successful API/training/browser observations from the first test phase of [full training run 41296845045](https://github.com/gig0d/web-application-security-lab/actions/runs/41296845045), owner commit `14952a1`. Per-observation SQLite/transport limitations remain visible.
- `compose-verification.json` and `compose-browser-evidence.json`: actual artifacts from that same successful run. They establish twenty real HTTP comparisons, restricted PostgreSQL/read-only behavior, independent database/restart behavior and nine browser checks against the Docker/PostgreSQL pair. The workflow also verifies direct controller actions, non-empty progress preservation, effective isolation and two volume resets.
- `assessment.json` and `assessment.md`: generated from the hosted training observations plus Docker browser evidence. The JSON preserves both input-file SHA-256 values. All twelve prevention results are backed by actual observations; XSS and CSRF include browser proof. This assessment does not establish networking or ZAP outcomes by itself.
- `screenshots/`: actual control-center desktop/mobile rendering and the stored-XSS comparison pages captured during local Playwright execution. Original artifact references describe the original run's locations; selected portable copies are here.
- `zap/hardened-active.*`: actual bounded active ZAP 2.17.0 reports from the same `14952a1` training run. Both the seeded HTML search path and SQL-backed ticket-search API were targeted explicitly.
- `zap/hardened-passive.*`: actual authenticated passive ZAP reports from the completely passing [hardened security run 41296837710](https://github.com/gig0d/web-application-security-lab/actions/runs/41296837710), also on `14952a1`. Its separate Python job verifies PostgreSQL integration and static/dependency gates; the container job verifies image separation and runtime inspection.

The active and passive scans each reported four **informational** observations: authentication request identified (10111), sensitive-information-in-URL heuristic (10024), session management response identified (10112), and user-controllable HTML attribute heuristic (10031). The URL used synthetic search data, not a real secret. A controllable attribute is not executable-XSS proof; actual browser regressions separately verify their specific sinks. Neither scan reported a high, medium or low alert. These results do not certify general security.

Cookie/CSRF/password values are redacted from scanner artifacts. Adjacent redaction records retain original and sanitized hashes; scanner observations are preserved. Exact bytes of retained JSON/scanner files are exempt from Git newline conversion so provenance remains verifiable. Both final workflows passed on the corrected application source. Consult `docs/verification.md` for the full execution record and the Windows Docker Desktop verification limit.
