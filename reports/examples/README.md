# Actual example evidence

These artifacts were generated by real executions on 2026-11-01. They are retained teaching examples, not prepopulated dashboard completion results or claims about a future checkout.

- `local-test-evidence.json`: unmodified observation file from the combined Windows/Python 3.13.18/Chromium execution: 105 passed, 1 local PostgreSQL skip. It includes 52 actual scenario observations. The development worktree was in progress; this file is execution evidence rather than a claim that every observation corresponds to a single clean Git revision.
- `assessment.json` and `assessment.md`: generated directly from that successful test evidence. The JSON includes input-file SHA-256 provenance and the database/transport/browser limitations. The twelve recorded prevention results include real browser observations for XSS and CSRF. SQLite/transport-fixture observations are not Docker network evidence.
- `screenshots/`: actual control-center desktop/mobile rendering and the two stored-XSS comparison pages captured by Playwright. No screenshot or browser result is fabricated. Original artifact references in the test record describe the original run's file locations; selected portable copies are here.
- `zap/`: actual authenticated passive ZAP 2.17.0 reports downloaded from [hosted run 41289670450](https://github.com/gig0d/web-application-security-lab/actions/runs/41289670450), owner commit `f33bd02`. The container/scanner job passed, while that run's Python job failed on a subsequently corrected lint annotation. Cookie/CSRF/password values are redacted; the adjacent redaction record preserves original and sanitized file hashes. Scanner observations were preserved.

The passive scan reported four **informational** observations: authentication request identified (10111), sensitive-information-in-URL heuristic (10024), session management response identified (10112), and user-controllable HTML attribute heuristic (10031). The URL used a synthetic search term, not a real secret. The attribute observation identifies a controllable value; it does not establish executable XSS. The browser regressions independently verify escaped rendering and script prevention for their specific sinks. No high/medium/low vulnerability is invented from these informational results.

`compose-verification.json`, `compose-browser-evidence.json` and `zap/hardened-active.*` are actual artifacts from the completely passing [full isolated training run 41291288113](https://github.com/gig0d/web-application-security-lab/actions/runs/41291288113), commit `0d83e76`. That active scan also reported four informational observations, with no higher-risk alert. Its scope was the HTML search path; a later plan additionally targets the actual SQL-backed ticket-search API and must be judged by its own execution evidence.

The completely passing [hardened security workflow](https://github.com/gig0d/web-application-security-lab/actions/runs/41291200554) on the same commit separately verifies PostgreSQL integration, static/dependency gates, hardened image separation, runtime inspection and authenticated passive scanning.
